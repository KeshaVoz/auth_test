# Backend-приложение аутентификации и авторизации

## Описание
Данное приложение реализует собственную систему аутентификации и авторизации пользователей. Основная задача — управление доступом к ресурсам на основе ролей и прав.

## Функционал

### 1. Взаимодействие с пользователем
- Регистрация: ввод ФИО, email, пароля и повтор пароля.
- Обновление профиля: изменение пользовательских данных.
- Удаление аккаунта (мягкое): user `is_active=False`, logout.
- Вход (Login) и выход (Logout) из системы.
- После login пользователь идентифицируется в последующих запросах.

### 2. Система разграничения прав доступа
- Продуманная схема управления доступом.
- Таблицы ролей и правил доступа.
- Ошибки 401 (Unauthorized) и 403 (Forbidden) при отсутствии доступа.
- API для администраторов по управлению правами доступа.

### 3. Минимальные бизнес-объекты
- Имитация бизнес-логики на фронтенде.

## Используемые технологии
- Python 3.11
- FastAPI
- PostgreSQL
- JWT для токенов
- bcrypt для хеширования паролей
- sqladmin — административный интерфейс для управления базой данных и объектами
- alembic — создание и применение миграций

## Запуск приложения

1. Клонировать репозиторий
2. Активировать виртуальное окружение
4. Запустить миграции базы данных
5. Запустить сервер:
uvicorn main:app --reload
6. Использовать приложенный dump file, чтобы развернуть бд с готовыми пользователями, способными зайти в админку(login: super@user.com password:superuser, login: admin@user.com password: admin)
ЛИБО
6. Через клиент доступа к базе данных создать Role с именем SuperUser или Admin, а также обязательно Role с именем User(присваивается всем новым пользователям)
7. Создать пользователя для наделение его правами суперюзера или администратора для доступа к админ-панели(доступна только для пользователей с Role SuperUser или Admin) через форму регистрации(через бд пароль не захешируется) по адресу /front/t_reg
8. Связать заранее созданного  юзера с экземпляром Role с именем SuperUser  или Admin
9. Зайти в админ-панель по почте и паролю
10. Менять роли созданных пользователей для получения доступа к админке или admin правам на фронте

## Структура проекта
- `app/` — код приложения (модули пользователей, авторизации, ролей)
- 'alembic' — миграции
- 'venv' — виртуальное окружение
- `.env` — конфигурационные переменные окружения
- `README.md` — текущий файл документации
- 'auth_test_task.dump' — дамп фаил с базовыми пользователями
